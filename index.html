04 What is a Workflow?

A YAML file in .github/workflows/. Hover / tap any line to see what it does.

name: CI

on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: npm test
name

What shows up in the Actions tab. Cosmetic, but future-you will thank you.

on

The trigger. Events, branches, tags, paths, cron. This is the whole "when".

jobs

A workflow has 1..n jobs. Jobs run in parallel by default — use needs: to chain them.

job id

test is the id you reference in needs: and in branch protection rules.

runs-on

Which machine. ubuntu-latest, windows-latest, macos-latest, or your own self-hosted runner.

steps

Run in order, in the same workspace. First failure stops the job.

uses

Pull in a reusable Action from the Marketplace. checkout clones your repo — the runner starts empty.

with

Inputs for that Action. Think function arguments.

run

Just shell. If it runs in your terminal, it runs here.

👆 Hover the YAML

Workflow → Jobs → Steps. That is the entire mental model.

07 What is a Monorepo?

One repository. Many independent services. One history, one PR, one review.

monorepo/
├── frontend/   # React
├── api/        # Go
├── worker/     # Node
├── shared/     # types, utils, protos
└── .github/workflows/
👍 Why teams like it
  • One atomic PR changes API + frontend together
  • No version-bump dance across 4 repos
  • Shared code is just an import
  • One CODEOWNERS, one CI config, one place to look
👎 What it costs you
  • CI gets slow and expensive — fast
  • Naive setup: every push builds everything
  • Blast radius of shared code is real

10 The hard case: shared/

One file. Three consumers. Path filters alone will lie to you.

shared/types.ts
frontend imports the type
api generates from the schema
worker parses the same payload
1. Fan-out filter

List shared/** in every service's paths. Dumb, works on day one, over-triggers forever.

paths:
  - 'api/**'
  - 'shared/**'
2. Detect & dispatch

One changes job uses dorny/paths-filter, outputs booleans, downstream jobs guard on if:. One source of truth.

needs: changes
if: needs.changes.outputs.api == 'true'
3. Real build graph

Let a build tool answer "what does this actually affect": Nx, Turborepo, Bazel. Dependency-aware + remote cache.

npx turbo run test \
  --filter=...[origin/main]
Rule of thumb: path filters until it hurts, then a build graph. Both are in .github/workflows/ of this repo — go read them.
